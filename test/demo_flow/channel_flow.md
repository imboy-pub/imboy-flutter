# DF-01 频道发现 → 群聊协作 → 群日程 → 钱包转账

> 状态：`部分通过 / 高风险段阻塞`
> 优先级：P0
> 类型：现有能力组合演示，不新增产品功能

## 1. 目标

验证用户能否从频道发现开始，完成内容消费、进入群聊、创建群日程、确认参加，并在明确授权的测试环境中完成钱包转账结果回传。

这不是“频道预约”功能验收。群日程只代表活动时间和参与确认；钱包转账只代表转账，不代表自动 AA、托管、退款或费用分摊已经存在。

## 2. 业务链路

```text
频道发现
  → 订阅频道
  → 查看频道内容
  → 进入群聊
  → 创建群日程
  → 确认参加
  → 钱包转账
```

## 3. 前置条件

- [ ] 使用本地或明确的非生产环境。
- [ ] 测试账号 A 可以发现并订阅测试频道。
- [ ] 测试频道已有可查看内容。
- [ ] 已明确频道到群聊的实际入口；如果当前产品没有自动绑定，使用频道分享/转发到群聊作为替代，并记录差异。
- [ ] 测试账号 A 对目标群有创建群日程权限。
- [ ] 如执行转账，必须使用隔离测试钱包、测试收款账号，并取得人工授权；默认只验证转账页和取消路径。
- [ ] 付费频道仅在测试环境已启用付费能力且存在测试订单时执行；否则标记为阻塞。

## 5. 端到端验收标准

- [ ] 每个跳转都能从上一步自然到达下一步，或明确记录当前产品的人工替代入口。
- [ ] 订阅、创建日程、确认参加、转账等写操作均有服务端成功证据。
- [ ] 失败时页面不会把乐观状态误报为成功。
- [ ] 付费频道、钱包转账未满足条件时，流程结果为 `阻塞`，不是 `通过`。
- [ ] 完成后能回答：用户是否能从频道内容走到一个真实群体行动，而不是仅仅打开了几个页面。
