# AI 真机视觉验收准则

本文件定义 AI 视觉模型对真机截图的**可复现判据**。模型只负责发现和解释候选问题；功能成功必须仍由 Flutter/Patrol、服务端响应或日志断言决定。

## 结论等级

| 结论 | 含义 | 处理 |
|---|---|---|
| `PASS` | 无规则冲突，或与已批准基线差异在阈值内 | 可作为视觉层通过 |
| `FAIL` | 明确违反硬规则 | 阻断对应 case |
| `REVIEW` | 视觉模型低置信度或检测到非预期差异 | 保存截图，人工或强模型复核 |
| `BLOCKED` | 无真机、基线或所需主题/数据 | 不得写成 PASS |

## 硬规则

1. 不得出现 RenderFlex overflow、黄黑条、裁切、重叠遮挡或不可读文本。
2. 主要操作、取消/确认、返回及危险操作必须完整可见；键盘、底部安全区、Toast 和弹窗不得遮挡它们。
3. 纯图标按钮必须有可读语义；可点击区域应不小于 44×44pt。
4. 颜色、间距、字号、圆角使用项目 Token；明暗模式均应保持文本可读。
5. 长中文、长英文、金额、空态、错误态和加载态均不得造成布局断裂。
6. 资金、E2EE、删除和外发操作必须呈现清晰风险提示，视觉通过不等于允许执行。

## AI 评审输入与输出

每次视觉评审必须输入：当前截图、可选批准基线、case 的 `visual.rubric`、设备尺寸、主题和语言。模型只返回 JSON：

```json
{"result":"PASS|FAIL|REVIEW|BLOCKED","confidence":0.0,"findings":[{"rule":"no_overflow","severity":"P0|P1|P2","bounds":[0,0,0,0],"reason":""}]}
```

当 `confidence < 0.85`、存在 P0/P1 finding，或截图与基线差异超过阈值时，结果必须是 `REVIEW`，不得由低成本模型单独判定通过。

未登记批准基线时，模型即使给出 `PASS` 也会由执行器降级为 `REVIEW`；这只可用于收集候选视觉问题，不能形成回归通过证据。

执行顺序：先用 `scripts/auto_test.py visual-diff` 做确定性筛选；仅 `REVIEW` 截图再通过 `visual-request` 交给视觉模型。这样绝大多数无变化截图不消耗模型调用。
