## 对本计划用例设计的三个直接输入

1. **canary 扫描 oracle 范式**：设备显示 == 发送文本 + 服务端全表面
   （消息行/归档/日志/对象存储）canary 0 命中——本计划 F03/F04 的
   case-map oracle 列应直接采纳该双面结构，替代单面 UI 断言。
2. **撤销场景的可观察失败**：G03 踢人要求"D 端不能取新 key/不能解/服务端
   recipient snapshot 不含 D 设备"——与合同 §6「群撤权负例必须观察被撤销者
   实际请求/解密失败」完全同构，F04-S03 的负例设计以上游 G03 为蓝本。
3. **W1–W4 注入点目录**：本计划 F03 若做 MITM 类 L2，须沿用上游已定义的
   四类注入点与 dart-define 端点指向本地代理的插入方式，不另发明。
