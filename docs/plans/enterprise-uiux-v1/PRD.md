## 核心结论（300字以内）

本次不重建企业客户端，只完成三个页面的展示收口：频道保留一个负责返回的头部，统计不永久占位，错误和筛选可辨识；工作台统一入口容器，只留“应用”而不暴露联调地址；坐席三态共用掩码姓名、安全摘要、可读来源的信息骨架。已有修复先复验，不重复重写。全部保留接口、权限、分页、接单及 OA 免登行为，以真实路由 Widget、360/1280亮暗大字矩阵和真机证据分别验收。

## 1. 产品目标、用户与边界

| 用户/任务 | 成功判据 | 不包含 |
|---|---|---|
| 企业成员阅读频道 | 进入详情后可定位频道；同一详情层只有一个返回入口；发布流不出现聊天输入框 | 新建频道业务、成员模型、群聊重构 |
| 企业成员从工作台进入业务 | 相同导航入口有相同图标/文本起点和容器；无重复办公入口及调试 URL 文本 | 新建应用市场、替换 OA 目的站点、改变 SSO |
| 客服坐席辨识与打开会话 | 现有安全摘要在三态按同一规则展示；来源可读；不泄漏未掩码身份 | 新增工单/SLA、改变接单/关闭/转交权限 |

**允许改动：**页面布局、局部纯展示组件、展示字符串/i18n、图标、基于既有状态的外观、展示层展开/收起状态、Widget/单元/golden 测试及任务文档。

**禁止改动：**API 路径/请求参数/DTO 解析、数据库、Provider/Service/Domain 的业务状态机、掩码算法、权限/feature 判断、CAS、SSE、消息/加密/附件生命周期、分页和排序算法、统计请求策略、OA URL/桥/鉴权行为。测试覆盖和代码生成输出属于工程配套，不放宽业务边界。

不得为通过截图修改全局 Token 数值、全局字体缩放、发布配置或启用被关闭的 feature。现有 `AppSizes` / `AppRadius` / `AppBreakpoints` 可复用；颜色/间距/字体必须来自现有 `AppColors` / `AppSpacing` / `FontSizeType`。找不到合格 Token 时记录 `BLOCKED_TOKEN`，不可私造颜色或全局改色。

## 3. 设计依据及数值合同

所有尺寸为 Flutter **逻辑像素**，不是手机物理像素。下列是 IMBoy 的设计选择，不是竞品实测尺寸。基础 Token 值已由 C10 核实；本地值若变化先重新量测并登记，不在页面重写旧数值。

| ID | 设计规则 | 具体目标与 Token 表达 | 依据/取舍 |
|---|---|---|---|
| D01 | 不重复导航职责 | 详情区域1个返回/关闭导航动作、1个频道身份标题；保留全局 rail/工作区上下文 | R01/R02；允许文章标题，不允许重复频道标题 |
| D02 | 内边距与触控 | 页面内边距16=`regular`；组距24=`xLarge`；图标与正文12=`medium`；命中区至少48×48=`xxxLarge` | R17；选择比 iOS44更大的跨端统一目标，图形本身可小于命中区 |
| D03 | P1 紧凑元信息 | 头像48；头像与文字12；元信息内容区最小高度64=48+8+8；实际随换行增长 | R02/R15；去重复大标题，不增新详情路由，不固定高度裁剪 |
| D04 | P2 入口行 | 无副标题最小56=48+8；有可信业务说明最小72=48+24；图标占位24；不为凑两行制造副标题 | R06/R09；本产品数值，不是 Lark/WeCom 的像素规范 |
| D05 | P3 会话行 | 同类行最小88=48+24+16；垂直 padding12、行间4；name→preview→source；大字自然增高 | R10/R11/R12；共享信息槽位不等于锁死三行/同一像素高度 |
| D06 | 大字与缩放 | scale1标题最多1行省略，安全摘要1行；scale2允许摘要最多2行、辅助信息换行、操作区换到下一行；禁止裁剪/缩小字体规避 | R17；缺省内容和业务按钮仍可达，不要求所有内容首屏可见 |
| D07 | 宽窗口 | 保留现有 shell 断点600/900/1200；页面使用实际可用内容宽度，不以整窗1280强行排两列 | C11/R09/R11；本轮不引入新导航或常驻多栏，避免现有分栏冲突 |
| D08 | 文本与颜色 | 正文用 subheadline/footnote/caption2 等已存在字体枚举；普通文本对比4.5:1、可用图标/状态信息3:1；语义主题颜色随亮暗切换 | R17；禁用 WCAG 例外不等于允许看不见，保留标签和 disabled 语义 |
| D09 | 内容工具 | 默认“搜索+筛选入口”；标签/全部·精华进入同页可展开区域；展开/收起不改查询；已生效筛选有可见指示 | R01/R11及C04；少占默认高度，代价是首次调标签多一次点击 |
| D10 | 空态/错误 | 首屏错误：48图标→间距12→标题→间距8→说明→间距16→重试；小空间允许整体滚动 | R16；图标不是所有空态强制项，CTA必须绑定真实可用动作 |

对于数值断言，记录组件 `RenderBox` 的实际高度/命中区域。大字下比较最小高度与不溢出，不与 scale1 的固定高度比较。颜色测试使用最终合成的前景/背景，不能仅比较 Token 名称；禁用/静音/选中是不同状态。

## 4. P1：内容型频道详情

### 4.1 页面结构

```text
现有企业/桌面 shell（不新增）
└─ 频道详情导航头：返回 | 频道名 | 现有更多菜单/私聊入口
   └─ 可滚动内容区
      ├─ 讨论引导：图标 + 去群组讨论 + 单个方向指示
      ├─ 元信息：头像 | 现有角色标签、已有订阅数（不重复频道大标题）
      ├─ 动作区：现有管理/订阅或静音/转发/分享，按原角色可见性
      ├─ 搜索 + 筛选入口
      ├─ [展开时] 标签、全部/精华；已选条件指示
      └─ 内容列表 / 首次加载 / 空态 / 首屏错误 / 分页尾部错误
底部：现有发布栏，仅原 canPublish 成立时出现；不添加聊天输入框
```

布局示意不是新的业务顺序要求：保留发布栏键盘避让、滚动控制器和现有 shell 的导航职责。若现有祖先也拥有同一详情导航，优先调整 P1 宿主展示而非改全局路由；真路由无法局部解决时标记越界阻塞，不删全局 topbar。

### 4.2 功能需求

| ID | 产品要求 | 可观测断言 | 行为不变约束 |
|---|---|---|---|
| P1-01 | 消除重复头部 | 完整路由语义树中，详情的返回动作1个；频道身份标题1个；点击返回只退原来1级；embedded/standalone 均覆盖 | 不改 go_router 路由、栈、DM 目标；HeaderBar 新展示参数默认行为兼容其他调用者 |
| P1-02 | 统计不是永久占位 | autoLoadStats=false、stats=null 时0个统计 skeleton；已有 subscriberCount 显示真实值；当前输入能表示未知时省略；若DTO已将缺省解析为0且不保留presence，记录数据边界，不能在展示层重新定义0 | 不发新统计请求；不把“创建者”角色徽标当作真实姓名 |
| P1-03 | 错误能理解和恢复 | 首屏错误有图标、加载失败标题、安全说明、重试按钮；一次点击调用原重试一次；分页失败仍看得到已有内容 | 不展示 raw exception、URL、Token；不更改错误分类或重试预算 |
| P1-04 | 动作可见且状态准确 | active/inactive-selected/disabled/pending 可区分；每动作≥48触控；缺回调不能表现为有效点击；静音是可切换状态而非禁用 | 使用既有可见性和原回调；不补造权限；不迁移 _toggleMute 的业务状态机 |
| P1-05 | 讨论引导只有一个方向符号 | 翻译字符串不含箭头；尾部最多一个 chevron；整行只有一个导航回调；scale2不溢出 | 继续打开现有群列表，不改成自动建群/加入群 |
| P1-06 | 工具区不常驻堆叠 | 默认不显示标签/分段输入；一次点击展开；收起保留值；query/tag/essence/page提交语义与原实现一致 | contentToolsAvailable 为false时仍不可用；不额外搜索，不改变分页或提交时机 |
| P1-07 | 日期只属于实际内容 | 空、无搜索结果、首屏加载/错误时日期分隔节点为0；有内容时每个可见日期后至少有对应内容项 | 不改数据排序、分组语义；只改变无内容情况下的装饰渲染 |

P1-01 中“只出现一个频道名”只计标题/身份区域，不错误禁止文章正文自然提及同名频道。动作与更多菜单可以并存，但本轮不扩大动作集合；移动某动作位置不是实现本 PRD 的前提。

### 4.3 状态文案

| 状态 | 标题/说明 | CTA |
|---|---|---|
| 首屏失败 | “频道内容加载失败” / “请稍后重试。” | “重试”，原重试回调 |
| 频道无内容 | “暂无频道内容” / “新的内容将在这里显示。” | 有既有可用发布动作才引导发布；只读者无发布CTA |
| 搜索无结果 | “没有找到相关内容” / “请调整关键词或筛选条件。” | 回到已有工具区；不新增跨数据层清理动作 |
| 分页失败 | “更多内容加载失败” | 原分页重试可用才显示“重试”；没有则保留现有恢复入口，不伪造 |

新增文案必须进入项目当前生效的 i18n 源文件；保持既有支持语言完整，生成器统一运行。已有等义文案优先复用。

## 5. P2：企业工作台

### 5.1 页面结构与入口保留

```text
现有工作台标题/企业上下文
同一亮暗主题页面背景
├─ 资源卡片（实际可见入口不为空时）
│  ├─ 客服工作台（原坐席 gate）
│  ├─ 项目（原 feature gate）
│  ├─ 群组 / 频道 / 附件（原条件）
│  └─ 每行：统一图标占位 + 名称 + 原导航指示
├─ [原条件成立时] Android 确认登录入口（业务保留、容器统一）
└─ 应用卡片：应用图标 + 应用 + chevron；无 URL 副标题
```

| ID | 产品要求 | 验收判据 | 影响与替代方案 |
|---|---|---|---|
| P2-01 | 统一背景/容器 | 所有导航组使用同一已存在的 insetGrouped/等价局部容器，边距16、组距24；亮暗颜色来自现有Token；不再出现上白下灰断裂 | 不修改全局主题；不为一致性引入新的组件库 |
| P2-02 | 删除办公而非删除 OA | 可见树中“办公”分组/应用列表为0；“应用”入口为1；既有 OA entries 仍供 bridge/按需免登使用 | 失去直接选择 OA 清单的入口是产品裁决；替代是保留现有应用入口，不扩展应用聚合页 |
| P2-03 | 不显示调试地址 | 应用行及其tooltip/semantics不含 appsUrl、http(s)地址；点击目标、WebView和免登参数与基线一致 | **隐藏文字不等于生产配置完成**：当前 test_oa.html 目的地址不在本次修改授权内；发布前另行确认 |
| P2-04 | 全部导航行统一图标槽 | 实际可见的客服/项目/群组/频道/附件/应用行图标槽24、间距12、文本起点一致；无业务副标题不补占位 | 不改变源资源顺序、可见性、权限及页面目标；Android确认登录行也不遗失 |
| P2-05 | 空组不留空壳 | 没有可见资源时无资源背景/分隔；仅应用时不额外加重复“应用”标题 | 不能用 resourceEntries.length 猜实际可见性；坐席widget隐藏时须使用已有可观察状态或局部布局，不复制权限规则 |

P2-05 若当前 `List<Widget>` 输入无法无副作用判断隐藏结果，允许使用同组逐行自然布局消除空背景，或保持原 gate 输出并在宿主做只读可见性投影；不调用 RenderObject 反推权限。无法满足时只阻塞该项，不删除其他入口。

## 6. P3：客服坐席工作台

### 6.1 共用信息骨架

```text
待接/处理中/已关闭（原Tab、徽标和数据来源）
会话行
├─ 第一信息层：掩码姓名 | [待接：已有等待时长]
├─ 第二信息层：[已有安全摘要；缺失按原隐私规则]
├─ 第三信息层：来源图标 + 用户可读渠道
└─ 动作区：待接=接入/接入中；处理中/已关闭=原打开会话动作
```

| ID | 要求 | 验收判据 |
|---|---|---|
| P3-01 | 三态使用同一姓名与摘要规则 | 同一DTO fixture在三态的掩码、摘要内容完全相同；只有等待和动作按状态不同；同名不同摘要可辨识 |
| P3-02 | 不获取/猜测缺失数据 | 只读取现有 `lastMessagePreview` 与 `hasLastMessage`；有消息但安全摘要为空时继续不渲染摘要，不显示“加密消息”或臆测附件类型；无消息复用/等义改写现有兜底 |
| P3-03 | 来源可读、未知安全 | `widget`→“网页咨询”；其他值仅在W0证实后建立映射；未知非空→“其他渠道”，空→“来源未知”；可见文字/读屏/tooltip不输出未知wire值 |
| P3-04 | 最小行高/大字一致 | 同类正常行≥88；name、summary、source顺序一致；scale2动态增高且按钮可见；不以空行补齐缺摘要，不强制三态像素高度相等 |
| P3-05 | 业务零变化 | queue/active/closed 请求、org/workspace、expected_version、onPageMeta、分页游标、SSE响应、跳转参数及claim次数与基线一致 |

**隐私底线：**姓名仍调用 `csMaskContactName`，不改函数、不增加真实头像、手机号、邮箱或原姓名tooltip；golden 仅使用合成客户数据；证据不含生产Token、原始会话内容。姓名同掩码且摘要缺失时仍可能无法唯一辨识，这是数据/隐私约束，不能以泄漏身份换取“全部可区分”。

**未读与末条时间：**本轮已确认使用到等待时长，但没有完成 DTO 末条时间/未读字段的端到端核验。本版本不新增这两项。W0若发现可靠现成字段，可登记后续展示候选，但不得自动扩大本次必做范围；不拿 `waitingSince`/列表长度替代。

## 10. 需求变化控制

P2空组、P3缺字段等辅助边界若需业务输入变化才能完全实现，必须记录受影响AC，不自动越界。批准删除办公是本包明确产品裁决，不是批准删除OA能力。原始问题已修复时，增加回归证据即满足任务；不得为了产生功能commit反复改写。
